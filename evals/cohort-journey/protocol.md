# Cohort observation protocol

Status: prepared; no participants or real-host results are recorded by this document.

Use the existing [fresh-session protocol](../live-session-reuse.md). Proposed initial pilot: six participants across first, related and interrupted tasks, in isolated project copies. Six is a practical starting scope, not statistical assurance. Recruitment/messaging requires separate explicit authorization. Keep evaluator inputs/answers outside producer copies and freeze public task/check versions before attempts.

1. Record exact project/engine/source/configuration, host/model/Node and launch options. Confirm actual host trust and fresh prompt/Stop observations through supported controls. An unavailable observation remains unknown.
2. Give the first public task. Observe expectation, setup, actual discoveries/decisions/checks, assistance, and what context is saved. Optional: ask the participant to explain one rule and find its record; this is research, not a required in-product quiz.
3. Give the related task in a genuinely new chat without the earlier transcript or the document hint. Observe actual context lookup/read/revalidation and a concrete rule carried into implementation. Run the separate evaluator against the resulting source.
4. Use supported interruption/resume for the interrupted task. Retain original run identity/status, relevant files and unrelated edits. Independently inspect recovery/persisted state. This evaluator alone cannot certify controller recovery.
5. Report every attempt, failure, interruption and intervention. Assisted completion is not unassisted success. Keep meaningful before/after evidence after repairs; different revisions have separate results.

Local commands: copy candidate/ to an explicitly separate scratch root; producers add their own legitimate tests. From the CYC source project, run `node evals/cohort-journey/evaluate.mjs ABSOLUTE_CANDIDATE first` or `related`. Treat candidate execution as code execution in that authorized isolated project. Use bounded host execution and clean up only owned services. This known exercise is development evidence; use held-out tasks for later effectiveness claims. Existing benchmarks remain frozen.

Use the existing experiment's optional report format or a simple local record with participant pseudonym, journey, actual prompt, source/configuration/host/model, start/end time if observed, assistance, behavior-probe path, context observations, recovery observations, outcome and limitations. Unknown measurements are null. Label machine-observed behavior, observer notes, agent-reported interpretation and participant report separately. A JSON record alone attests none of them.

No default remote telemetry. Redact secrets/tokens and keep sensitive transcripts outside distribution. Track confusion and optional willingness to reuse CYC. Repair/retest observed severe data-loss/privacy failures before claiming the corresponding flow ready. Report all pilot outcomes and dispositions; lower effort/causal superiority requires a separate controlled held-out comparison. Do not infer token savings from source size or add overlapping durations.
