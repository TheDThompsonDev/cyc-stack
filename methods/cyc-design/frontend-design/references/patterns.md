# Patterns

Each pattern here was seen working on one or more of eight production sites studied on 2026-11-21, at 1440 × 900 and 390 × 844, with sizes read from the live pages. They are grouped by the decision you are making. Pick by the visitor's job, not by taste, and build the whole pattern: a pattern with one part missing is usually the brochure again.

A pattern is not a look. The same pattern was seen on a white page, a cream page and a dark one. Choose the look in [the method's Step 3](../SKILL.md#step-3-choose-the-look-from-the-subject).

## First screen

Choose one opening. It decides what the page is.

Choose the first screen by the evidence the visitor needs. A finder can open on real choices and editable criteria; a schedule can open on dates and availability. The dealership comparison favored a photograph with the finder over it and actual vehicles directly below. Use that composition when seeing the scene helps someone choose.

- **Hero photograph with the task on it.** Use when a scene helps someone picture the place, understand the work, or desire the item. Build one photograph the full width of the screen and 70 to 90 percent of its height, behind the header or directly under it. It strikes when it has one subject, real light (dusk, a window, a lit counter), room for the text on one side, and fills the full width with no frame. Set on it a short headline in the chosen type voice, one sentence, and the task itself: the search bar, the booking bar or the one main button, on a solid panel so it reads. Place any time, cost or eligibility detail that changes the decision beside the task. Start the real items directly below the photograph, so the first row shows at the bottom edge or after one scroll. On a phone the photograph is shorter (45 to 60 percent of the screen) and the task panel sits below it at full width.
- **Search on the hero.** Use with the hero when the visitor came to find one option among many. Build the search as one panel on the photograph: two to four labelled parts with a gray prompt inside each ("Add dates"), one button in the action color, and a live count on the button ("Show 19 cars"). Real results start directly below the photograph.
- **Items under the hero.** Use with the hero when browsing is the job and the things have pictures. Build two full rows of real items directly under the photograph, each row named for a place, a time or a category taken from the data ("Newest on the lot", "Under $20,000"), each item with its own photograph.
- **Choices in view.** Use when the visitor chooses by comparing attributes or times. Build the finder or schedule beside real options with aligned facts, visible criteria and a path to inspect or select one.
- **Returning task first.** Use when many visitors already have an account or a booking. Build a compact band directly under the navigation that holds the returning task itself, with its fields visible (sign in, find my booking, track an order), and put the offer for new visitors below it.
- **One photograph, one panel.** Use when the offer is a single next step. Build one photograph the full width of the screen and about half its height, with one plain panel on it holding a headline, one sentence and one button. Nothing else competes.
- **Product as the picture.** Use when the visitor is judging software or a tool. Build a short centered headline, one sentence and two buttons, then the real product at readable size. Let it start inside the first screen and run off the bottom edge so the page invites the scroll.
- **Working surface.** Use when the site is the product. Build the working screen as the landing page, with real content a logged-out visitor can use, and keep the offer to sign up in one bar pinned to the bottom edge.
- **Person doing the task.** Use when a service asks for trust. Build the headline and buttons on one side and, on the other, a photograph of a person doing the thing the service helps with, run to the edge of the screen and faded into the canvas. Lay two or three pieces of the real product over it, such as a question, an answer and a follow-up.
- **People and the next date.** Use when the visitor is deciding whether to join or attend. Build a large headline that speaks to them, a photograph of real members that runs to the edge, and the next real event as its own card inside the first screen with its date, time and one button.
- **Campaign photograph.** Use when the visitor came to see a collection and its style. Build one photograph of people with the product, edge to edge and most of the screen tall, with the offer set on it in display type and the buttons on it too.
- **Result before sign-up.** Use when the product returns a result, such as a score, a quote or a plan. Build a sample result beside the headline: the number, three counted categories and one line explaining a finding, labelled as an example.

## Navigation and header

- **Plain-word navigation.** Use on every site. Build three to nine category or task names in one row, with no icons, and put sign-in or the main action at the right end. Measured: 13 to 16 px text.
- **Header that stays.** Use when the page is longer than three screens. Build the header pinned to the top, 64 to 96 px tall on a desktop, with the main action always in it.
- **Search that shrinks.** Use with "Search on the hero". Build the large search bar so that on scroll it becomes a compact pill in the pinned header that restates the current search.
- **Action that wakes up.** Use when the hero already holds the main button. Build the header's copy of that button quiet at the top of the page and filled once the hero has scrolled away.
- **Context row.** Use when place or time changes what the visitor can get. Build one thin row above the header with what is true now: open or closed, the nearest location, the next slot, a phone number.
- **Trust line on top.** Use when the visitor is handing over money or personal data. Build one small line above the logo stating the protection that applies, such as the insurance, the license or the guarantee.
- **Rotating notice bar.** Use when there are two or three current offers. Build one bar above the header that rotates them, with previous, next and pause buttons.
- **Topic switch.** Use when one long page serves several kinds of visitor. Build a row of two to four topics that swaps the content below and then stays pinned. On a phone it becomes a pinned dropdown.
- **Leaving-the-site mark.** Use for any link that opens another site. Build a small diagonal arrow beside its label, in navigation and on buttons alike.
- **Text menu.** Use when a category has more than six children. Build the menu that opens under it as two or three columns of plain links with small gray column headings and generous space, no pictures.
- **Skip link.** Use on every site. Build "Skip to main content" as the first tab stop, hidden until focused. Seven of the eight studied sites have one.

## Records and cards

- **The picture is the card.** Use when items have photographs. Build each item as a photograph with text under it and nothing around it: no border, no box, no shadow. Measured: 180 px wide with a 12 px gap, seven across at 1440, pictures close to square.
- **Three facts under the picture.** Use for anything a visitor compares. Build the same lines in the same order on every item: what and where, the price as a total, and the rating or status. Example: "Cabin in Broken Bow · $635 for 2 nights · ★ 5.0".
- **Badge and save, fixed corners.** Use when items can be saved or carry a status. Build the status as a small pill at the top left of the picture and the save heart at the top right, in the same places on every card.
- **Shape tells the type.** Use when two kinds of thing share a shelf. Build one kind square and the other round, so a visitor can tell them apart before reading.
- **Portrait product photograph.** Use for clothing and anything worn or held. Build every product picture portrait, about 4 to 5, square-cornered, with the same framing and background.
- **Price first on a tile.** Use for a deal. Build the price large on the photograph, then the product name as an underlined link, then the old price: "$15 COZY TEES Was $29.95".
- **Old and new price together.** Use when something is reduced. Build the old price struck through directly beside the new one, with the reason or the deal name on the next line in the sale color.
- **Quiet demand strip.** Use when real sales or booking counts exist. Build a thin strip across the bottom of the picture with the count ("335 sold"). Never invent the number.
- **Product with checkmarked facts.** Use when products differ by terms, not looks. Build each as: its picture, a tag saying who it is for, the name, three or four checkmarked facts, then the actions. Every product identical in structure.
- **Two actions, ranked.** Use when an item has a safe step and a committing step. Build both as buttons, stacked, the safe one filled and on top, the committing one outlined below.
- **Highlight one line.** Use when one fact on one item is time-limited. Build a pale highlight behind that single line and a small tag naming it.
- **Compare box.** Use when items number more than about eight and differ by terms. Build a compare checkbox on every item and keep the filter button and the count pinned while scrolling.
- **Directory of faces.** Use when people are the proof. Build a grid of small portraits with names, four across, sixteen or more, linking to the full list.
- **Program in three facts.** Use to sum up a course, plan or service. Build three small capital labels with a value under each: duration, format, commitment.
- **Editorial tile in the grid.** Use on a long product grid. Build one tile with a photograph and a link to a related collection, placed in the grid in place of a product.
- **Colored category tiles.** Use when there are many categories and no photographs for them. Build a grid, four across, each tile one flat saturated color with the name at the top left and a small tilted picture at the bottom right.
- **Shelf with "show all".** Use when the page has several kinds of content. Build each as a row with a heading on the left, "Show all" on the right, and its own previous and next buttons.

## Results and filters

- **List and map together.** Use when place decides the choice. Build the list on one side and a map on the other that stays put while the list scrolls. Put the price on each map pin.
- **Search restated.** Use on every results page. Build the header to show what was searched, with a Filters button beside it and a heading giving the count ("Over 1,000 homes in Austin").
- **Count in the heading.** Use on every category page. Build the heading with the number of items in brackets after it, under a breadcrumb.
- **Fastest option first.** Use when same-day pickup or availability exists. Build it as a switch at the very top of the filters.
- **Collapsed filter groups.** Use when there are more than four filters. Build each as a closed group with a plus sign, in one column, with sub-category links above them.
- **Bigger pictures on results.** Use when a results page shows fewer items than the home page. Build the cards larger, with a dot row showing more photographs and three gray lines of facts.

## Trust and reassurance

- **Fear removed before the button.** Use on any action that feels risky. Build the sentence above the button so it names the fear and removes it: "See if you'll be approved before accepting."
- **Reassurance beside the action.** Use beside a consequential action when the visitor has a specific reason to hesitate. Build one short line or three small items stating what it costs and what it will not do: "No credit card required", "No impact to your credit score", "Cancel anytime".
- **Practical line under the button.** Use on an upload, a booking or a form. Build one small gray line answering the practical questions: what is free, how long it takes, which files or details are needed.
- **Numbers instead of adjectives.** Use wherever the page would otherwise praise itself. Build three numbers with labels from the real data: members, events a year, price to attend.
- **Named testimonial.** Use only with a real person's words. Build the quotation with the name, the role and the specific program or product they used.
- **Example labelled as an example.** Use whenever sample data is shown. Build a small capital label on it: "Illustrative example". Never present invented results as real.
- **Limits stated.** Use when the product is new or partial. Build one plain sentence in the first screen saying so.
- **Footnotes that connect.** Use for regulated or conditional claims. Build a numbered mark on the claim, linked to the note, with all notes collected at the foot of the page.
- **Privacy as a real choice.** Use for analytics or tracking consent. Build the notice with analytics off until allowed and with Decline and Allow as buttons of equal size.

## Plans and prices

- **Period switch with the saving.** Use when billing has two periods. Build a two-part switch above the plans with the saving stated beside it.
- **One plan made dominant.** Use when one plan suits most buyers. Build it filled with the dark or brand color, with the only filled button and a small tag. Keep the others pale.
- **Plan as five lines.** Use for every plan. Build the name, the price with its unit, one line saying who it is for, a full-width button, then a checklist that begins "Everything in [the plan before], and:".
- **Plans grouped by purpose.** Use for four or more plans. Build two panels, each with its own headline, and put two plans in each.
- **Risk row.** Use directly under a pricing heading. Build three short items that remove risk: what is free, how to cancel, what the buyer keeps.

## Words

- **Headline about the visitor.** Use for a service or a community. Build the headline as their situation or a question to them, with the product's name nowhere in it: "What are you building?"
- **Steps as an eyebrow.** Use when the product is a short process. Build a small capital line above the headline that lists the steps in order.
- **Facts as headings.** Use for section headings. Build each from a fact in the organization's own voice: "Pizza at six. Talks at 6:45."
- **Buttons that name the place.** Use on every button. Build the label from where it goes or what it does: "Shop Women", "Find a meetup", "Check my eligibility". Never "Learn more" or "Get started" alone.
- **Two buttons, two jobs.** Use when the hero has a second action. Build the main one filled with an arrow and the second outlined with an icon that shows what it is, such as a play mark for a demonstration.
- **Empty state with a way forward.** Use for any list that can be empty. Build one sentence of help and one button inside the empty space: "Create your first playlist. It's easy, we'll help you."

## Phone

- **Bottom bar.** Use when the site has three to five destinations a visitor moves between. Build a fixed bar at the bottom with an icon and a label for each, the active one in the action color.
- **Action in the header.** Use when one action matters most. Build it as a small filled button in the phone header beside the menu, on every page.
- **One-pill search.** Use with "Search on the hero". Build the search as one full-width pill, 56 px tall, that opens the full search.
- **Chips for categories.** Use when a desktop tab row will not fit. Build the categories as a row of chips that scrolls sideways.
- **Row with the next item cut off.** Use for any shelf. Build it to scroll sideways with a little over two items showing, so the cut edge says there is more.
- **Pinned filter pills.** Use on a product grid. Build two pills, one for category and one for filter and sort, that stay pinned under the header, with the grid two across.
- **Picture first.** Use with the hero photograph, "One photograph, one panel" and "People and the next date". Build the photograph at the top and the headline, sentence and button below it at full width.
- **Shorter headline.** Use when the desktop headline wraps past three lines at 390 px. Build a shorter one for the phone and keep the same button.
- **Notice as a sheet.** Use for an announcement or an offer. Build it as a centered dialog on a desktop and as a sheet rising from the bottom on a phone, with one plain way to close it.
