# CYC project context

Read this index first, then only the docs whose Covers match the paths you are about to change, and the error ledger for that area. `cyc investigate --path ...` does the matching and compares each covered file with the hash its newest change record gave it; `cyc context history <doc>` shows what earlier runs did to a component and how their checks ended; `cyc context lint` checks these rows against the docs, the change records and Git.

This is context for developing the CYC source checkout. An installed application uses its own project context; the engine's copied documentation is not that application's component map.

Component docs live in this folder in the layout the Context method fixes (Covers, Current view, Lessons): they say what is true now. What each run did is in `changes/`, one record per run and one digest per earlier month, written by the controller after the checks pass. Reference rows point to maintained documentation elsewhere; they are matched like component rows and `cyc context index` leaves them as written.
