## Current view

The public entry remains /cyc. README, CYC/Setup/Scout/Deliver and the response standard explain a first task through outcome/preserved behavior, a consequential discovered rule and decision/check, then actual evidence, limits and linked target context. Examples are illustrative, never synthetic observations. Existing instructions already required understandable progress; this extension supplies a concrete first-task contract without personal tracking or another mandatory report. Code/requirements revalidation takes precedence over stale project prose. User understanding and unseen-task benefit require actual observations.

response-mode.responseGuidance is a pure projection of observed preference: concise offers expand once and limit off/on; OFF, expanded and project presentation omit the footer, project mode exposes no CYC controls, and unknown state stays unverified. It never invokes a hook, changes a preference or claims activation. lengthCommand and native gate semantics are unchanged; quoted/embedded/ambiguous commands cannot toggle. New messages are guidance for agents, not guaranteed emitted strings.

catalog.routeTask retains the old advisory playbook choice and adds consequence-based guidance from description/scope. Routine wording/Markdown signals require confirmation, consequential signals call for existing focused high-risk scrutiny, and unknown impact calls for investigation. These are leads, not an exhaustive impact scanner; canWaiveRequiredChecks is always false. The CLI route and run-next projections surface it without changing stages, policies, budgets or receipts. Test adoption-journey covers APIs/CLI and refusal states. The full configured suite remains required; model effectiveness/effort are unmeasured.
