## Current view

A controller execution has an explicit capability: native-codex, native-claude, cursor or intentionally requested standalone. scripts/execution.mjs:resolveExecution separates the real host conversation, a workflow label and the controller run ID. A label's shape does not select Cursor. Runtime assertRunOwner binds the recorded conversation and native gate to the actual caller, including gate-only starts; no-hook or foreign callers cannot borrow the target's stored label to resolve its owner.

The entrypoints are run start, packet/check-reply, and runtime mutations. Native modes require observed context and cannot be downgraded to standalone while a native request is active. Native delivery still checks tokens, request windows, source freshness and exact responses where required. Cursor needs an explicit exact-response packet. Standalone completion writes local delivery evidence without certifying host activation; hexadecimal conversation IDs remain standalone on resume.

Work queue (2026-11-19): bin/cyc.mjs adds the `queue` command (create, status, next, decide) and accepts an optional `queue` field in the run start file. For a run bound to a queue unit, compact adds a `queue` entry to run start, next, finish and complete results saying where the line stands. It is read from queue and run state and changes no result, ownership, stage order or exit code; a queue that cannot be read costs only the advice, and an unbound run gets none. `--queue` is refused outside the queue command. A queue belongs to the project, not to a conversation: any conversation may ask for the next unit or record a decision, and the calling session is stored with the queue and with each decision. Each bound run keeps the ownership rules above, so only the conversation that started it can change it. Run ownership across two real conversations was not exercised for bound runs.

Queue board (2026-11-20): bin/cyc.mjs adds queue post, board, wait and release, and queue next --seat review --session ID. Posting or waiting with --run, and moving a bound run's read mark, pass assertRunOwner and, for a run with no execution record, also need the caller to be the session the run recorded (speaksFor in scripts/runtime.mjs): assertRunOwner alone lets anyone change such a run, which is how every run started from a queue start file is stored. A caller is the session its host reports; board commands take --session, which counts only when the host reports none. A review seat is refused for the conversation that owns the unit's run (compared by session, conversation and gate key) and, once taken, is used only by the conversation that took it. A post with neither run nor seat is the person's; from a conversation that owns an open run of the queue or holds a seat it is accepted only to relay the person's answer.

After the live trials (2026-11-20): bin/cyc.mjs accepts --session on every queue action, including create, status, next and decide, where it changes nothing: the hook tells a conversation to pass its session, and a live builder's first command was refused for it. On board commands it still names the caller only when the host reports no session. The queue's note of each run it admits now also records the session the host reported at start (by), and speaksFor in scripts/runtime.mjs accepts that session as well as the one the run recorded, so a run started under a label of its own is still its starter's on the board.

The hub (2026-11-20): bin/cyc.mjs adds the hub command and its --port option. The hub reads queue status, the board and run histories with no caller identity and no ownership check, because it changes nothing: it posts no message, moves no read mark and starts no run. Anyone who can open the local address sees everything the queue recorded. When answering from the page is built, that changes and needs the board's rule for who is speaking.
