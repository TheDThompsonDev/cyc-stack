## Current view

The source-only journey map links installation, actual host activation, completion/recovery and fresh-chat reuse to existing checks and observable outcomes. It adds no controller stage or mandatory parallel reporting system. Use the existing investigation/recipe registry, configured final checks and focused target context.

The live-session protocol requires distinct host IDs without resume/fork/history injection, actual record discovery/read, current revalidation and a concrete rule carried into the related task. An evaluator checks behavior separately from hook and context-use observations. Prompt context must be observed in the same client that executes the task; API hook discovery alone is insufficient. A missing native prompt must not be silently downgraded and counted as native qualification.

The November 14 pilot report records local installation preservation/refusal, actual native CLI prompt/Stop observations, two distinct chats, controlled stale-artifact rejection and original-thread interruption recovery through a corrected development controller. It preserves earlier failed probes, the stopped source-repair plan, separate proof/check roles and local evidence hashes. Consult the completing verification run's change record for final broad results and source bindings.

Native ownership recovery belongs to execution-ownership.md: use actual caller evidence, preserve the original run and budgets, and keep alias compatibility distinct from canonical identity. Do not copy disposable runtime state or host configuration into source. Keep raw tokens/transcripts local-only; share a sanitized result with evidence availability limits.

The follow-up review also found a task-context consumer still applying an incompatible host order after the owner guard. Its direct pre-change/after tests and correction are reported separately from the earlier native recovery's source bytes. A passing known-fixture journey or broad suite does not qualify a conflicting-identity setup it never exercised.

Invocation-only hook trust is separate from interactive trust. A controlled wrapper forwarding actual host events qualifies only its stated case. Remove only pilot-specific trust entries during teardown and preserve unrelated bytes. Neither tests, hashes, a controller pass nor agent review proves human acceptance, unseen-task effectiveness or efficiency.

Run the configured source suite and distribution checks after changes; validate local documentation links and bind public claims to retained observations. Repeating the pilot requires current engine/skill/source manifests and a fresh client observation, not reuse of an earlier acceptance label.
