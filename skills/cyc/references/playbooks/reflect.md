# Reflect and improve

Use to learn from completed work, failed attempts, or repeated user corrections. Stages: [remember](../../../../methods/cyc-remember/SKILL.md) → [reflect](../../../../methods/cyc-reflect/SKILL.md) → [deliver](../../../../methods/cyc-deliver/SKILL.md).

Gather original interventions, artifact outcomes, actual checks, and effort/rework evidence. Use secondary conversation reports cautiously; repeated summaries of one event do not create independent examples.

Distinguish user preferences, project conventions, reusable procedures, executable checks, and temporary workarounds. Tie each proposed improvement to a specific mismatch and observed consequence. Preserve authorship and whether a suggestion was adopted. Include where the lesson does not apply and a practical evaluation that could disprove its usefulness.

Apply skill or instruction changes only when the user's request includes implementation. Do not silently convert local habits into global policy. If the apparent improvement rests only on model praise or self-reported success, seek outcome evidence or narrow the conclusion.

**Acceptance:** a small set of supported proposals, or an honest finding that evidence is insufficient.
